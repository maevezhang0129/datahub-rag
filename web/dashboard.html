Corpus

Chunk size

Token counts per chunk, bucketed. The target is — tokens; a source that never reaches it is producing one short chunk per document rather than a split.

Index state

Embeddings live in one table per model, so several can be indexed side by side. Every chunk also records the document content_hash it was cut from, so a revised document that has not been re-chunked is detectable rather than merely unlikely.

Relevance gate calibration

MIN_RELEVANCE was set from the gap between answerable and unanswerable questions on this corpus (ADR 005). That calibration holds only while the gap does — changing the corpus or the embedding model can move it. This is the view that shows whether it has.
